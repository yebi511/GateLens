## MODIFIED Requirements

### Requirement: 网关段内展示内部尝试链

页面 MUST 保留现有输入表单与跨网关分段，直接从所属网关的记录、上下文标识和后端确认连接展示内部尝试，MUST 不读取或重建完整 `attemptGroups`。重定向 MUST 不额外增加网关跳数。已确认顺序的尝试 MUST 在本上下文内编号，以连接说明表达“内部重定向，继续下一次尝试”；无法确认顺序时 MUST 使用记录名称及关系未确认提示，不输出确定的先后箭头。多个上下文 MUST 保持视觉隔离；Segment 的汇总关系状态 MUST 不抹去其他上下文已确认的局部连接。

尝试卡摘要 MUST 包含可用的 Provider、上游模型、Route 和响应码。redirect 记录 MUST 标为“中间响应”；非 redirect 记录 MUST 根据观察结果标为“终止尝试候选”、网关局部终止尝试或“最终响应”，不得仅凭 HTTP 200 自行升级归属。

#### Scenario: 单网关两个尝试
- **WHEN** 同一网关内存在有序的 400 redirect 记录与后续 200 记录
- **THEN** 页面在一个网关卡片内显示两次尝试及内部重定向连接说明，网关段数量保持一个

#### Scenario: 跨网关关联
- **WHEN** 两个网关共享本次 probe ID，并且各自包含 redirect 记录
- **THEN** 页面分别在所属网关卡片内展示记录及上下文，不将不同网关的所有记录合并成一条内部尝试链

#### Scenario: 顺序存在歧义
- **WHEN** 某个上下文没有后端确认的顺序且关系或顺序未确认
- **THEN** 页面保留全部记录，并显示“同请求多条记录，关系未确认”及原因，不使用确定的尝试编号或因果连接

#### Scenario: 已确认与未知上下文共存
- **WHEN** 一个网关的上下文 A 有确认连接，上下文 B 关系未知
- **THEN** 页面隔离两个上下文，在 A 显示已有连接，在 B 显示记录和未知说明，不从 Segment 汇总状态推导出额外连接

### Requirement: 按需展开尝试详情

页面 MUST 默认展开包含内部重定向或 HTTP 错误的网关请求上下文，普通单记录探测 MUST 保持紧凑展示。每条记录 MUST 提供可通过键盘操作的详情展开入口，展示既有 Route/upstream、响应详情、ext_proc、日志来源及关联依据。新增摘要 MUST 使用固定 AI 路由字段，不默认铺开包含问题和回答的完整 `ai_log`。上下文分栏、折叠及展示标题 MUST 由精简协议数据生成，不要求公开 Group 对象。

#### Scenario: 存在中间错误
- **WHEN** 结果包含失败后发生内部重定向的记录
- **THEN** 中间失败与后续尝试在首次呈现时可见，无需用户先展开整个网关上下文

#### Scenario: 普通单记录与详情
- **WHEN** 结果仅有一条普通访问日志且 AI 摘要不存在
- **THEN** 页面仍紧凑显示 Route 和响应码，用户可展开既有 upstream 与 ext_proc 详情

### Requirement: 明确显示重定向证据缺口

页面 MUST 从结构化问题列表在对应网关卡片内显示内部过程缺口，并在请求证据区按需汇总；同一问题在汇总列表中 MUST 不因数据复制而重复计数。仅有 redirect 标记但无后续记录时 MUST 显示“已发生内部重定向，后续尝试记录缺失”；仅有同请求多条普通日志时 MUST 显示关系未确认，不得将其自动标为 redirect。采集结束、取消、读取错误和有效结果中的未知状态 MUST 按实际证据表达，不推断具体故障原因。问题说明措辞 MUST 不影响状态判断。

#### Scenario: 重定向后续缺失
- **WHEN** 采集结束后仅有 redirect 记录，且 Agent 实际响应为 HTTP 200
- **THEN** 页面同时保留 HTTP 200 请求结果和“后续尝试记录缺失”提示，不补造成功尝试卡片

#### Scenario: 普通记录关系未知
- **WHEN** 多条访问记录共享 probe ID，但没有 redirect 标记
- **THEN** 页面展示关联记录及关系未确认提示，不显示“一次重定向”

#### Scenario: 网关问题汇总
- **WHEN** 一个网关报告日志读取失败问题
- **THEN** 网关详情与请求证据汇总均可展示该问题，但数据只保存一份，汇总只计为一个问题

## REMOVED Requirements

### Requirement: 兼容旧结果和窄屏交互

**Reason**: 用户确认前端、Server、Agent 同步升级，不再保留旧结果回退；窄屏和无障碍约束迁移到新要求。

**Migration**: 使用版本 2 的精简探测结果；缺少版本或不支持版本时明确提示协议不支持。窄屏、长文本换行、键盘操作和文字状态继续按“精简协议与窄屏交互”要求验收。

## ADDED Requirements

### Requirement: 精简协议与窄屏交互

页面 MUST 仅接受版本 2 的探测结果，MUST 不使用旧顶层 `hops`、旧 `attemptGroups` 或旧摘要字段回退。版本缺失或不支持时 MUST 显示明确的协议错误。有效结果的未知状态 MUST 正常展示，MUST 不恢复最后一条即最终上游的规则。窄屏时 MUST 在网关卡片内纵向排列尝试摘要和详情，长 Route、模型、cluster 与响应详情 MUST 可换行；成功、错误、redirect、未知状态 MUST 同时有文字标识，不仅使用颜色区分。

#### Scenario: 不支持的结果版本
- **WHEN** 接口返回旧探测字段且没有版本 2 标识
- **THEN** 页面提示探测协议版本不支持，不把结果解释为没有日志或请求成功

#### Scenario: 有效协议中的元信息缺失
- **WHEN** 版本 2 结果的日志缺少确认尝试关系所需的身份或顺序信息
- **THEN** 页面保留记录及 ext_proc 详情，显示关系未确认，不输出无依据连接或最终上游

#### Scenario: 窄屏与键盘访问
- **WHEN** 用户在窄屏查看长 Route 的 redirect 链，并使用键盘展开尝试详情
- **THEN** 所有文字在卡片内可读，详情入口可聚焦和操作，各状态均有文字说明
