# GateLens MVP 路线图

## 阶段 0：验证输入

- 选定一个首发网关及明确版本。
- 收集匿名化 Gateway、Route、推理扩展、Service、EndpointSlice、状态样本和 10 条典型请求。
- 建立兼容矩阵：资源类型、支持字段、状态来源、不可解释行为。
- 为样本写人工预期路径，作为后续 conformance 基线。

验收：明确哪些结论来自规范、实现或运行时证据。

## 阶段 1：只读拓扑与静态解释

- Kubernetes 采集与不可变快照。
- Gateway API 基础拓扑、引用完整性、状态诊断。
- 请求模拟 API 和可视化路径。
- 首发网关/推理扩展适配器的最小子集。

验收：样本的输出路径与人工基线一致，每步可回链到源对象。

## 阶段 2：运行时证据

- OpenTelemetry Trace（trace ID 直查）。
- Prometheus 健康/错误率指标。
- 访问日志连接器及证据强弱标记。
- 配置推断与实际观测的差异视图。

验收：具有关联 ID 的样本请求可展示入口到上游的事实时间线。

## 阶段 3：多实现与多集群

- 第二个网关实现适配器。
- 插件兼容性清单与适配器 conformance fixtures。
- 多集群权限隔离、快照比较、版本变更影响分析。

验收：相同规范化查询跨两个实现可用，并显式展示差异。

## 暂缓决策

不在设计阶段固定前端、后端语言或存储。阶段 0 之后根据团队现有栈、部署环境和资源规模确定；优先考察 Kubernetes Watch、图查询、快照版本与 OTel 集成的成熟度。
